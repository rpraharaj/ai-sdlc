# Ship notes

Describe **what actually shipped**. Source of truth is the commit range.

## Is this the right skill?

| Signal | Do this instead |
| --- | --- |
| Tag / publish / deploy | `cut-release` after notes |
| Why we chose X | `record-decision` |

## Required inputs

- Git range (default: last version tag → HEAD)
- Existing changelog format if the repo has one

If this is not a git repo or the range is empty, **stop**.

## Human decisions (do not invent)

- Version bump (only if they asked)
- Performance/security wins not in the commits

## Procedure

1. `git log` / `git diff --stat` on the range.
2. Detect format: `CHANGELOG.md` / fragments / host release body / reply-only Added/Changed/Fixed.
3. Match heading, date, and version prefix from the last entry. Do not switch formats.
4. User-facing first. Drop typo-only commits. Call out breaking changes and migrations from the diff / `data-change` plans.
5. Do not mention agents or “generated by.”

## Output

- Path: existing changelog or the reply
- Template: [references/notes-template.md](references/notes-template.md)

## Quality bar

- [ ] Range named
- [ ] No invented features or metrics
- [ ] Breaking/migration called out or n/a

## Done

Range, path, whether you bumped a version. Next: `commit` or `cut-release`.
